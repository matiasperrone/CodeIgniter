Upgrading from 2.2.6 to 2.3.0

Before performing an update you should take your site offline by replacing the index.php file with a static one.

CodeIgniter 2.3.0 runs on PHP 5.6 through PHP 8.5. Applications that already ran on 5.x keep working: every change below is either invisible on PHP 5 or has a documented opt-out.

Step 1: Update your CodeIgniter files

Replace all files and directories in your "system" folder and replace your index.php file. If any modifications were made to your index.php they will need to be made fresh in this new one.

Note: If you have any custom developed files in these folders please make copies of them first.

Step 2: Add the new config items

Two new items are read from application/config/config.php. Both have safe defaults, so adding them is optional:

$config['composer_autoload'] = FALSE;
$config['encryption_driver'] = 'auto';
  • composer_autoload: set it to TRUE to load vendor/autoload.php (next to index.php, or else application/vendor/autoload.php), or to the path of a custom auto-loader. With it enabled, packages added with composer require are available everywhere in your application. A missing auto-loader stops the request with an explanatory error.
  • encryption_driver: see Step 4.

Step 3: Database drivers

The extensions behind the mysql (removed in PHP 7.0), mssql (7.0) and sqlite (5.4) drivers no longer exist in modern PHP.

  • A configuration that still says 'dbdriver' => 'mysql' now transparently uses mysqli when the mysql extension is missing. The default in application/config/database.php is now mysqli.
  • A configuration that says 'dbdriver' => 'mssql' now uses sqlsrv when the mssql extension is missing and the sqlsrv extension (Microsoft's PECL package, which also needs the Microsoft ODBC driver on Linux) is installed. A host:port hostname is rewritten to the host,port form sqlsrv expects.
  • Selecting mssql without either extension, or sqlite without its extension, stops with a message pointing to sqlsrv / pdo, instead of a fatal error.
  • The sqlsrv driver's persistent connection (pconnect = TRUE) never returned the connection and so always failed. It does now.
  • The pdo driver now really sets PDO::ERRMODE_SILENT (the option was ignored before). PHP 8 throws exceptions by default, so without this fix a failed query would throw instead of returning FALSE as it always did on PHP 5/7.

Step 4: Encryption class

The mcrypt extension was removed from PHP in 7.2. The Encryption class now supports two backends, chosen with $config['encryption_driver']:

  • 'auto' (default): mcrypt when the extension is loaded, otherwise OpenSSL. Existing sites keep working untouched, and data encrypted before the upgrade still decodes.
  • 'mcrypt': always mcrypt (on PHP 7.2+ it has to be installed from PECL; its functions raise deprecation notices which the class silences).
  • 'openssl': AES through OpenSSL.

Compatibility between the backends: OpenSSL can read and write everything mcrypt produced with the rijndael-128 cipher (all modes of set_mode() except mcrypt's 8-bit ofb), the byte format is identical. It cannot read data produced with rijndael-256, which is the default cipher: that is the 256-bit block variant of Rijndael, which OpenSSL does not implement. With the OpenSSL backend rijndael-256 is mapped to AES, so it works but is a different format. If you have stored data (cookies, database columns) encrypted with the default cipher and you are moving to a PHP without mcrypt, decode it while mcrypt is still available and store it again, or call $this->encrypt->set_cipher('rijndael-128') in the code that wrote it before migrating.

The MCRYPT_* constants are no longer needed: set_cipher('rijndael-128') and set_mode('cbc') take the plain strings. The initialisation vector now comes from random_bytes() instead of mcrypt's weak MCRYPT_RAND.

Step 5: Behaviour that was fixed

These were bugs that produced wrong results or PHP errors, and are now corrected on every PHP version:

  • XML_RPC_Values::iso8601_encode() used format codes that do not exist (%i, %s) and returned values such as 20231114T22:%i:1700000000. It now returns 20231114T22:13:20.
  • create_captcha() returned an empty word when none was supplied, and could loop forever on PHP below 7. A new word_length option (default 8) controls the generated word.
  • The Zip class stored the wrong modification time for files read from disk.
  • The Unit Testing class report was empty on PHP 8.
  • The Output class passed NULL to string functions when a controller produced no output.
  • CI_Input::valid_ip() raised a TypeError on PHP 8.
  • The XML-RPC library's parser registry no longer uses the parser as an array key (an XMLParser object on PHP 8).

Step 6: Things to check in your own code

  • PHP 8.2+ deprecates creating undeclared properties. The framework's classes are marked #[\AllowDynamicProperties] (a plain comment on PHP 5/7), so your controllers, models and libraries that extend them are unaffected. Declare the properties on your own base classes if you want to be ready for PHP 9.
  • Replace calls to functions PHP removed in your own code: each(), create_function(), mysql_*, mcrypt_*, get_magic_quotes_gpc().
  • PHP 8 compares 0 == 'text' as FALSE (it was TRUE), and throws a TypeError when you pass NULL or a wrongly typed value to many built-in functions.

Running the test suite

The distribution now ships a dependency free test suite that runs unchanged on PHP 5.6 through 8.5: php tests/run.php, or tests/run-matrix.sh to run it under every installed interpreter.
